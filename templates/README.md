# MindForAI 模板库

这里收录可直接复用的 `.mindforai` 文档模板。当前版本合并为一份汇总模板 [`Templets.mindforai`](./Templets.mindforai)：把真实项目文档、任务看板、常用工作方法与代码审查流程放在同一棵树里，打开后按分支取用，比拆成多个小文件更直观。

模板不是“填空表格”，而是给人和 AI 共用的一份结构化上下文。保留能约束行为的节点，删掉不适用的分支，比从空白文档开始更快。

## 汇总模板：Templets.mindforai

根节点 `MindForAI-Templets` 下按场景分为四支：

| 分支 | 内容 | 适合怎么用 |
| --- | --- | --- |
| 示例项目A: mindforai | 项目核心文档、已完成 / 处理中任务、TODO、使用说明 | 参照它整理自己的项目定位、模块编号、任务看板与交付流程 |
| 示例项目B: BeamStreamS3 | ESP32-S3 Wi-Fi 麦克风：硬件约定、固件模块、串口 / Wi-Fi 协议、配置项与任务记录 | 软硬件结合项目的完整拆解范例，可换成自己的硬件与模块 |
| 作者常用的工作方法 | 本机 Agent 操作 Docker、一键部署脚本、Web 版 AI 常用方法（代码审查 / 隐私审查）、启动旧项目的第一步 | 直接复制需要的节点喂给 Agent，省去反复交代工作方式 |
| 我们的终极目标 | “1文档 + 1Agent = 1项目” | 作为整份文档的收束，也是模板设计的原则 |

### 分支里有什么

- **项目核心文档**：项目概述、目标结构、模块编号规则、模块清单、关键约定与常见任务。
- **任务看板**：`已完成的任务` / `处理中的任务` / `排队中的任务` / `TODO`，按状态推进任务。
- **TODO**：基本要求、规则、自定义命令、建议、禁止行为、交付代码审核要求，以及 Subagent 使用约定。
- **缺陷报告**：错误现象、预期现象、复现信息与修复记录。
- **一键部署脚本**：脚本注释规范、交付物要求、三大操作系统启动脚本与 Docker 一键部署约定。
- **代码审查 / 隐私审查**：固定审查范围、结论格式、敏感信息检查清单与 Git 提交说明要求。

## 怎么使用

1. 下载 [`Templets.mindforai`](./Templets.mindforai)，放进项目根目录，或直接拖进 [MindForAI](https://fantasylincen.github.io/mindforai/) 打开。
2. 保留需要的分支，删除与当前项目无关的示例，改成自己的项目内容。
3. 把“排队中的任务”拖到 `TODO` 下，或直接修改“本次工作”的内容。
4. 右键复制 `TODO` 节点（或按 `Ctrl + C`），直接喂给 Agent。
5. 开发完成后暂存修改，导出 `Patch.patch`，交给“代码审查”流程；审查通过后提交代码，把任务节点拖到“已完成的任务”。

## 使用建议

- 模板只是起点，删掉不适用的分支，保留能约束 AI 行为的节点。
- 单个程序文件的职责描述保持一句话，不把实现细节写进代码地图。
- 作为 AI 规则使用时，把「规则」与「禁止行为」放在树的靠前位置，减少模型忽略约束的概率。
- 建议配合项目核心文档使用：先让 AI 读 `project.mindforai` 建立全局认知，再读任务文档领取任务。
- 一个任务只写一个可验证的结果，验收标准尽量写成可以逐条勾选的条件。
- 需要长时间调研或需要用户决策时，提前写进规则，避免 AI 自行假设。

## 脱敏说明

仓库中的示例均已做通用化处理：

- 不包含真实密钥、令牌、账号或密码。
- 不包含真实内网 IP、无线网络名称、设备名或个人目录。
- 不包含真实姓名、邮箱、仓库所有者或私有项目资料。
- 涉及地址、路径、端口的地方使用 `<占位符>` 或示例值，请在复用前替换。

如果你要把自己项目里的文档整理成模板提交，请先删除密钥、账号、内网地址、个人路径、日志片段和任何不适宜公开的内容。

## 欢迎提交模板

如果你有一套经常使用、效果稳定的文档结构，欢迎提交 PR：

1. 新建一个 `.mindforai` 文件，文件名使用小写英文与连字符；也可以把多个场景合并成一份汇总模板。
2. 在本文的模板说明中补充一行说明。
3. 确保文件能被 MindForAI 正常打开（`type: mindforai` 与 `version: 1` 是必需的文件头）。
4. 附上使用场景与适用对象，方便其他人判断是否复用。
5. 确认内容已脱敏，不包含密钥、账号、内网地址、个人路径与私有数据。
